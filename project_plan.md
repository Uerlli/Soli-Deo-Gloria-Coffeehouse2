# Soli Deo Gloria Café — Website Oficial

## 1. Project Description
**Posicionamento:** Website editorial/institucional que traduz a experiência física do Soli Deo Gloria Café para o digital. O objetivo não é "informar que o lugar existe", e sim construir uma percepção sobre ele — fazer o visitante sentir que entrou no lugar antes de conhecê-lo fisicamente.

**Público-alvo:** pessoas que valorizam experiência, atmosfera, café especial, arquitetura, natureza e cultura. Público local (visita) + público amplo (descoberta de marca).

**Valor central:** "O LUGAR É O PROTAGONISTA." Emoção + função. Sofisticação natural, ousadia controlada, movimento a serviço da percepção.

**Escopo:** site sem venda online (por enquanto). Sem login, sem pagamento, sem carrinho.

## 2. Page Structure
- `/` — Home cinematográfica (hero em tela cheia + narrativa por scroll)
- `/o-lugar` — O Lugar / Espaço (arquitetura, natureza, atmosfera)
- `/cardapio` — Cardápio (cafés, comidas, doces)
- `/o-cafe` — O Café (grãos, origem, preparo como ritual)
- `/experiencia` — Experiência / Eventos (encontros e ocasiões)
- `/sobre` — Sobre / A história do Projeto Soli Deo Gloria
- `/visita` — Visita (localização, horários, contato, informações úteis)
- `/faq` — FAQ / Informações úteis
- `*` — NotFound

## 3. Core Features
- [ ] Design system próprio (paleta terrosa, tipografia editorial, ritmo)
- [ ] Navegação fixa que atravessa o hero e solidifica ao rolar
- [ ] Hero cinematográfico em tela cheia
- [ ] Narrativa por scroll (revelação progressiva, parallax sutil)
- [ ] Seção "O Lugar" com fotografia estrutural
- [ ] Cardápio por categorias (cafés, comidas, doces)
- [ ] Seção "O Café" — origem, grão, preparo como ritual
- [ ] Galeria audiovisual / atmosfera
- [ ] Área de Experiência / Eventos
- [ ] Visita — mapa, horários e contato
- [ ] FAQ com Schema.org FAQPage
- [ ] Instagram / redes sociais
- [ ] Rodapé editorial
- [ ] SEO por página + dados estruturados

## 4. Data Model Design
Não é necessário banco de dados nesta fase. O site é editorial/institucional.
Cardápio, informações e dados de contato são conteúdo estático versionado no código.
(Nenhuma tabela, nenhuma autenticação, nenhum pagamento.)

## 5. Backend / Third-party Integration Plan
- Database: **não necessário nesta fase**
- Shopify: **não** (sem venda online por enquanto)
- Stripe / Pagamentos: **não**
- Formulário: eventual formulário de contato/novidades via recurso de Form (quando definido)

## 6. Development Phase Plan

### Phase 1: Fundação + Home cinematográfica
- Goal: construir a base visual (paleta, tipografia, navegação, rodapé) e a home completa.
- Deliverable: design system aplicado, nav + footer, home com hero em tela cheia, manifesto, prévias do lugar/café/cardápio, galeria e CTA de visita.

### Phase 2: O Lugar + O Café
- Goal: aprofundar "o espaço" e "o produto como ritual".
- Deliverable: páginas `/o-lugar` e `/o-cafe`.

### Phase 3: Cardápio + Experiência
- Goal: entregar a informação de forma clara e sensorial.
- Deliverable: páginas `/cardapio` e `/experiencia`.

### Phase 4: Sobre + Visita + FAQ
- Goal: história do projeto, como visitar e dúvidas.
- Deliverable: páginas `/sobre`, `/visita` e `/faq`.

### Phase 5: Polimento
- Goal: animações, transições entre páginas, SEO final, responsividade e revisão de detalhes.
- Deliverable: site completo revisado e pronto para publicar.
